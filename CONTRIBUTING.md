# Contributing to Ghosthread AI

Thanks for wanting to help. This file explains what kinds of
contributions are useful, what this repository is (and isn't), and how
to get in touch.

---

## What this repository is

This repository is the **official documentation** for Ghosthread AI.
It does not contain the software. The Ghosthread AI application is
proprietary, closed-source, and distributed separately.

That shapes what "contributing" means here.

## What you can contribute

### Bug reports

If you find something wrong in the documentation — a broken link, an
out-of-date description, a typo, a missing concept — please open a
[documentation issue](../../issues/new?template=bug_report.md).

Good bug reports include:

- Which file and which section
- What you expected to read
- What you actually read
- A suggested correction, if you have one

### Feature requests and product feedback

If you have an idea for the software — a capability you'd like to see,
a workflow that doesn't feel right, something that's missing — open a
[feature request](../../issues/new?template=feature_request.md).

I read every one. Not every request gets built, but every request gets
read.

### Security reports

**Do not open a public issue for security problems.** See
[SECURITY.md](SECURITY.md) for the correct disclosure process.

### Translation

If you'd like to translate the documentation into another language,
reach out first at **ghosthreadai@gmail.com**. Translation is welcome,
but I want to be involved in the process so the translations stay
accurate and official.

## What you cannot contribute right now

### Code

This repository doesn't contain the software's source code. I'm not
accepting code contributions at this time. This is a deliberate choice
for the beta phase.

If you'd like to write code for Ghosthread — a plugin, an integration,
a companion tool — please open an issue first and describe what you
have in mind. There may be a way to collaborate even without this
repository being the vehicle for it.

### Marketing content, promotional text, or branding changes

I maintain the project's voice and its public identity myself. Please
don't open PRs to "improve" the README's tone, replace sections with
marketing copy, or adjust terminology. If you think the docs could be
clearer, open an issue and tell me where — I'll rewrite it in my own
words.

## Style guide for documentation contributions

If you're proposing a documentation change, keep it consistent with
what's already here:

- **Plain English.** Short sentences. Concrete examples. No filler.
- **No marketing language.** Avoid "revolutionary", "game-changing",
  "seamless", "cutting-edge", or similar words.
- **No emoji in prose.** (UI mockups and diagrams can have them.)
- **Honesty over polish.** If something is broken, undocumented, or
  uncertain, say so. This project values being told the truth about
  itself.
- **Attribution stays intact.** Don't remove the author's name, the
  copyright line, or trademark notices.

## How to submit a change

1. Fork the repository.
2. Create a branch with a descriptive name
   (e.g. `fix-typo-in-glossary`).
3. Make your change.
4. Submit a pull request using the provided template.

Small fixes — typos, broken links — may be applied directly. Larger
rewrites will be reviewed for tone and accuracy.
